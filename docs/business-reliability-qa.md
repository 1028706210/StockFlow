# 2026-10-27 业务完整性与可靠性验收

## 实现

1. 订单商品快照：新单保存skuCode/skuName/unitPrice，改名后历史不变；旧明细NULL不回填当前名称，界面明确未知。
2. 日期和金额：订单/履约、流水、审计、盘点支持含首尾自然日范围，订单额外支持精确金额范围；非法与倒置范围400。Hash保存查询、状态、页码、容量和范围，刷新/返回恢复，换账号隔离。CSV按当前角色与筛选导出，UTF8 BOM、双引号转义、防公式注入，最多10000条、超限422。
3. 入库单：DRAFT→CONFIRMED或CANCELLED；来源、1..10种商品，每种1..1000000件；幂等创建、确认与整单事务，商品快照、关联流水和审计。
4. 退货单：买家本人COMPLETED订单整单申请REQUESTED→CONFIRMED或CANCELLED；仓管验收实物可再次销售后入库。订单锁确保每订单最多一张有效/成功退货，取消后允许重申请；原订单状态不改，无退款。
5. Flyway：仅一个运行时迁移机制；空库B004→005→006，已知V004旧库受结构校验保护后登记baseline4，未知/损坏库拒绝；版本校验、重启不重复执行、clean禁用。
6. 运行：/api/health为存活，/api/health/readiness为数据库就绪200/503且不泄漏细节；运行指标仅仓管/管理员可读，固定状态桶、累计请求耗时和超时任务结果。

## 交付边界

本轮本机Work设置关闭浏览器控制；用户表示会开启，但工具当前仍拒绝浏览器访问，因此未用其他途径绕过该设置，未声称桌面/手机真实页面验收通过。前端已有状态级测试和静态模块加载检查，视觉/真实操作需要控制开启后补验。CI当前状态以 [PR1检查](https://github.com/1028706210/StockFlow/pull/1/checks) 为准。

咨询助手既有实现保留，仅将本仓库规则同步为入库单和整单退货，不把规则问答描述为大模型。外部Node项目本轮未修改，重新使用其同步脚本时需合并本仓库新增业务规则，避免旧规则覆盖。没有真实支付/退款/物流、多仓库或公网部署。
