# ADR-001：StockFlow 前端演进与 Vue 迁移评估

日期：2026-10-30。评估基准：本地aa1ff2e（应用代码fd24866）。状态：完成选型评估；尚未批准或实施框架迁移。

## 决策

当前保留原生ES Modules前端，继续收敛模块职责，并完成第三阶段剩余页面验收。暂不全量迁移Vue。若后续页面、交互或协作需求使声明式组件具有明确收益，再单独批准Vue 3只读页面试点，以实际结果决定扩展范围。

这不是认定原生JavaScript长期一定更好。当前项目目标为Java后端实习／校招，已有RuoYi课程项目使用Vue，StockFlow的主要区分度来自库存事务、幂等、并发、履约、流水和可验证交付。为技术栈名称重复重写前端，现阶段收益不足以抵消回归与构建成本。上述成本收益是工程判断，不是工时测量。

## 当前代码事实

- 主入口app.js为69528字节、720行，注册13种业务视图；集中处理身份、路由、列表、商品选择、订单、盘点和导出。大小和行数只用于定位职责集中程度，不是质量评分或性能结论。
- 已拆出api-client、query-state、ui-model、document-state、business-documents、ui-helpers和inventory-reports。请求、查询模型与部分业务UI已有边界，无须从零重写所有逻辑。
- index.html仍集中定义视图和弹窗，styles.css集中定义主要视觉样式；部分模块虽然行数少，每行却含多条语句，行数不足以判断复杂度。
- requestJson携带同源会话、写入CSRF及请求超时，并在返回前后检查身份epoch。app.js的request包装器另处理401／403与登录清理；迁移时只复用底层fetch函数会漏掉这一层行为。
- clearSession和activateSession清理分页、详情、单据尝试、弹窗与咨询助手状态；旧异步结果不得写入新身份。不能把角色按钮隐藏当作服务端权限控制。
- 地址hash由既有路由和query-state维护，包含筛选和页码。当前样式和粒子效果与Vue无必然关系，换框架不自动提升美观或速度。
- app-flow测试使用VM加载入口、去除静态import，并使用轻量DOM夹具。它可继续验证旧页面行为，但不能直接证明Vue模板挂载、响应性和卸载正确。
- RuoYi-Vue3/package.json实读Vue 3.5.26、Vite 6.4.1。这是课程项目声明的依赖版本，不是StockFlow依赖，也不是已安装版本或最新版声明。

对应源文件指纹见../evidence/2026-10-30-frontend-assessment.json；指纹是本次快照，后续改动可合法导致不同。

## 备选方案

| 方案 | 收益 | 新成本与风险 | 本次选择 |
|---|---|---|---|
| 保留原生JS，按职责整理 | 复用已验证交互、维持现有JAR交付 | 仍需主动维护状态边界和可读性 | 当前采用 |
| Vue 3只读页面试点 | 评估模板、局部状态和组件测试是否降低维护成本 | 增加构建及两种渲染方式的边界管理 | 满足需求后再评估实施 |
| 一次性Vue全量迁移 | 最终技术写法统一 | 同时重做身份、路由、单据、弹窗、测试与交付，难以隔离回归 | 当前不采用 |

Vue官方支持渐进采用，也提供无需构建的使用方式；这说明局部接入可行，并不证明本项目必须迁移。参考：[Vue使用方式](https://vuejs.org/guide/extras/ways-of-using-vue)。Vite官方说明了后端集成和构建产物manifest的衔接；引入构建意味着交付流程也需验证。参考：[Vite后端集成](https://vite.dev/guide/backend-integration)。

## 适合重新评估的真实触发条件

持续新增复杂表单或复用交互，出现明确的重复修改；多个开发者长期在同一入口产生冲突；修复局部状态频繁影响无关页面；或者需求明确要求交付Vue前端。由问题记录和具体变更样本证明这些成本，不按行数达到某个任意阈值就重写，也不预设迁移能节省多少天。

## 若批准试点，实施边界

1. 先选择库存流水的只读列表区域；保留现有hash路由、筛选地址契约及跨页面详情回调。单个DOM子树由一种渲染方式独占，旧render与Vue不得同时改写它。
2. 请求继续经过同一身份包装器，保留epoch、请求序号、超时、旧数据保留和错误状态。登录、注册、库存写入、订单、退货及盘点继续沿用旧实现。
3. ui-model与query-state的纯函数可优先复用。直接构建DOM的ui-helpers和inventory-reports渲染逻辑不能原封不动充当Vue模板；应保留旧页面或按试点边界改写。不要为了试点同时引入另一套身份存储、Axios、Pinia或Vue Router。
4. 若使用Vue单文件组件与TypeScript/Vite，只用于试点新增模块；以已核对兼容版本和锁文件构建。开发通过同源代理访问后端，交付仍由现有JAR提供静态产物。后端API、Cookie、CSRF与库存模型保持一致。
5. 构建输出进入独立生成目录，由打包任务复制；禁止把清理输出目录指向既有静态源码。核对Spring Security对新增JS/CSS静态资源的放行范围，不扩大API权限。
6. 初次加载、离开页面、退出登录及身份切换必须有明确挂载／卸载清理；咨询助手继续使用现有会话事件，不保存另一份密码或身份。
7. 保留现有视觉令牌和粒子层，重点验收表格、焦点、键盘和390×844布局。Vue不承担默认视觉改版。

这是一份后续范围建议，不代表本轮已经创建Vue工程、安装依赖或完成试点。尚未选择包管理器、锁文件与构建插件，不向README添加未存在的启动命令。

## 试点的验收与回退门槛

- 同一账户及筛选条件下，条目、顺序、游标、空态、异常态、地址刷新恢复与旧版一致；详情关联跳转正确。
- 请求未完成时换账号或离开页面，旧结果不会回填；401／403处理仍遵循会话边界。未授权用户依然由后端拒绝。
- 新增实际组件挂载／卸载测试，继续运行原有前端回归、后端检查和JAR／容器交付验证；实际Edge桌面／手机操作单独记录。
- 只有取得同场景的测量结果后才比较资源体积和响应体验，不预先写性能提升百分比。比较一次真实功能修改所需触及的文件和理解成本，决定是否扩大采用。
- 保留旧视图的明确入口与单一选择配置，确保两版不会同时挂载；未达到门槛时切回旧视图。不要无限期维护双份业务规则。
