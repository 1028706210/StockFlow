# 买家业务范围核验

核验日期：2026-10-30。范围：单仓商品选购、本人订单履约及整单退货；不扩展支付、物流或仓库模型。

## 允许的买家能力

| 能力 | 业务约束 | 验证 |
|---|---|---|
| 注册、登录、退出 | 注册固定为 BUYER；Cookie 会话写操作要求 CSRF；退出使会话失效 | AuthenticationIntegrationTest |
| 商品浏览与选购 | 买家商品页仅查询在售商品；不提供改价、停用、入库、安全库存设置和库存明细 | 前端回归、InventoryVisibilityIntegrationTest、Edge 商品页 |
| 创建订单 | 每单最多 10 种 SKU，每种合并数量 1—99；后端确定金额、校验在售与库存；下单立即预留 | StockFlowIntegrationTest、OrderLinesTest；Edge 选购至草稿 |
| 查询、筛选及导出本人订单 | 归属取自服务端登录身份；不能通过订单号或筛选参数读取其他买家订单 | WorkbenchIntegrationTest、RevisionIntegrationTest |
| 确认、取消及收货 | 待确认可确认或取消；已确认不能取消；已发货由本人确认收货；重复成功操作不重复扣库 | FulfillmentIntegrationTest |
| 整单退货 | 仅本人已完成订单；退全部原商品与数量；买家可取消待接收申请；仓管验收回库 | DocumentIntegrationTest、DocumentQueryIntegrationTest；Edge 本人退货列表和已确认详情 |
| 工作概览与趋势 | 订单数量、金额、趋势限定本人；订单金额包含取消订单，不表述为实付金额 | WorkbenchIntegrationTest、OperationsIntegrationTest、Edge 概览 |
| 咨询助手 | 只读查询与规则说明，不代为下单、取消、发货或确认退货 | 前端规则与会话客户端回归 |

## 不属于买家权限的能力

商品创建与编辑、销售状态管理、入库单、直接入库、库存明细和导出、库存流水、预警、安全库存设置、盘点、对账、审计、全部订单查询和发货、退货接收回库、运行指标均属于仓管或管理员。既有后端角色校验保留；他人订单与退货资源返回 404，越角色接口返回 403。

真实支付、退款、快递查询、预计送达、部分退货、多仓、优惠券和积分均未实现，本轮未新增对应功能或承诺。

## 本轮修正

1. 买家导航、标题改为“浏览商品”和“我的退货”，首页描述、趋势说明与统计范围改为本人订单视角。
2. 买家商品页固定查询 active；直接携带 inactive 地址栏参数和重置筛选都不能切换为管理筛选。隐藏销售状态筛选，保留仓管查询停用商品能力。
3. 使用说明按身份生成。买家只看到选购、确认/取消、收货和整单退货步骤，不再要求切换仓管或其他演示账号。
4. 退货筛选 REQUESTED 的中文统一为“待接收”；商品分页的无障碍名称随买家视角调整。
5. 更新需求文档说明当前页面行为。未改后端写入逻辑、数据库结构或历史数据。

商品读取接口仍按既有契约允许已登录买家读取商品元数据（包括停用商品）；停用不是隐私标记。商品页与选购只展示在售商品，后端新建订单再次拒绝停用商品；订单历史快照不依赖商品当前状态。不能把页面筛选当作后端权限机制。

## 验证结果与边界

- 新增 4 项前端回归；修正前捕获商品筛选和帮助两处失败，修正后全部前端 96 项通过，0 失败、0 跳过。
- MySQL 后端共发现 102 项：101 项通过，0 失败、0 错误，1 项大数据测试因未启用其开关而跳过。测试限于 stockflow_test 和 stockflow_test_migration。
- 首次后端测试因本地私有 MySQL 未运行而连接失败；启动既有实例后完整重跑通过。没有用课程库 zzyl10。
- 最终 JAR 打包成功；本地 /api/health/readiness 返回 UP。
- Edge 桌面实操：买家登录；核验五个业务菜单；商品“详情/选购”与隐藏管理筛选；选购商品进入草稿且预览金额正确；买家专属帮助；直接访问 #inventory 回到概览；本人退货列表与详情不提供“确认收到并入库”；最终版待接收标签及分页无障碍名称。
- 本轮浏览器未新建、取消、发货或退回开发库中的真实业务单据；写流程和买家间隔离由真实 MySQL HTTP 集成测试覆盖。本轮未补做完整手机写入流程或生产安全审计。
- 本轮仅本地修改和核验，未推送 GitHub。
