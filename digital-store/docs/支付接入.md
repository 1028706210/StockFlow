# 支付与私有交付接入

状态：默认关闭，真实收款未开通。用户已选择跳过 Stripe 插件，不要求重新安装；现有 Stripe REST Checkout 适配只是待地区确认的候选，不等于账号已可收款。

## 为什么没有沿用 StockFlow 模拟确认

实物库存的买家确认、仓管发货和退货回库，不能证明数字商品已付款。新模块只维护托管结算与下载授权，没有银行卡输入表单、完整客户账户、库存预留或实物收货流程。

## 已实现的安全路径

1. 浏览器创建 HttpOnly、SameSite=Lax 会话，写请求校验同源 Origin 和 X-CSRF-Token。
2. `/api/checkout` 只接收商品ID及请求键，金额、币种、数量与可售状态来自服务端目录，不信任浏览器价格。同键重复请求复用结算，不同内容或支付模式冲突返回409。
3. 支付页面由 Stripe Checkout 托管。成功或取消跳转只是展示入口，不改变付款状态。
4. 回调使用原始请求内容核验 HMAC-SHA256、时间戳和多个 v1 签名；随后到平台回查会话和每一行商品的ID、金额、币种、数量、模式及绑定关系。
5. 只有平台付款状态为 paid 且会话完成后才授权。异步待付、失败、过期不发货；重复事件在 SQLite 事务中去重，迟到待付不覆盖失败或已付状态。
6. 下载需要当前会话拥有相应订单且订单包含该商品。私有目录没有静态入口，拒绝路径遍历和符号链接。响应使用 attachment 与 no-store。
7. 订单、事件与会话持久化；跨设备需通过 POST 恢复表单提交订单号和恢复凭据，错误尝试有限速。恢复凭据不能放进URL、日志或邮件示例中。

## 待经营者确认的选择

- 主体所在地区、主要买家地区，以及候选支付平台是否支持该主体。不要通过虚构地址或他人账号绕过地区限制。
- 结算币种、每个商品正式价格、税务和退款/隐私规则。
- 若选用提供成熟订单与文件交付的平台，可替换此候选适配并复用其交付能力，无需同时搭建多套商城。

Stripe 支持地区以[官方可用性页面](https://stripe.com/global)为准。目前项目不对未知地区作出可开户或可结算的承诺。

## 在本机接入平台沙箱

1. 经营者在平台官方后台建立测试环境，获取测试密钥及 Webhook 签名密钥，填入本地 `.env`；不要把任何密钥发送到聊天。
2. 设置 `PAYMENTS_MODE=test`、准确的 BASE_URL、`sk_test_` 与 `whsec_`。未配置完整时服务返回503，不生成假订单。
3. 在官方 Stripe CLI 登录测试账户，使用本机事件转发：`stripe listen --forward-to http://127.0.0.1:8094/api/webhooks/stripe`。使用该进程返回的测试签名密钥，通过环境配置加载。CLI 安装和登录由经营者在已授权设备完成，项目不捆绑凭据。
4. 网页加入已就绪的 SVG 商品，进入平台测试 Checkout。使用[官方测试支付资料](https://docs.stripe.com/testing)，不要输入真实银行卡。
5. 分别验证成功、取消、卡片失败、异步延迟与失败、重复事件、金额不符拒绝、订单刷新和正确文件；保存脱敏平台事件ID及页面截图。
6. Canva 商品需先完成复制链接核验，否则即便配置测试账户也不能结算该商品。

回调订阅：`checkout.session.completed`、`checkout.session.async_payment_succeeded`、`checkout.session.async_payment_failed`、`checkout.session.expired`。接口版本固定为官方当前文档中的 `2026-10-28.endive`，沙箱回调版本应与其对齐并再次验证。[版本说明](https://docs.stripe.com/api/versioning)、[回调签名与故障处理](https://docs.stripe.com/events/manage-webhook-endpoints)。

## 正式上线前的额外工作

正式模式需要显式授权与地区、币种、政策审核配置，并且每个商品的正式价格都已确认；不能仅修改一个mode开关。本地 `.env.example` 保持禁止状态，不提供可以直接上线的真实参数。

退款、争议后的下载权限吊销和经营者订单管理尚未实现；平台状态对账、网络不确定后的自动修复、告警、备份恢复演练、订单保存期限与客服流程均需补齐。当前代码没有被认定为生产支付系统，未完成这些事项和沙箱验收前不得启用 live。

本地 `scripts/verify-checkout.mjs` 会替换外部 HTTP，只测试协议与真实 ZIP 字节，既不是平台沙箱交易，也不是生产交易。不能把它的 PAID 测试状态当成真实订单。
