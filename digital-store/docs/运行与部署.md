# 运行、私有交付与部署说明

## 本地运行

需要 Node.js 24；商城服务器零第三方依赖。Windows 可直接运行 `启动商城.ps1`，或使用 `node --env-file-if-exists=.env server/start.mjs`。默认仅监听127.0.0.1:8094，收款关闭。StockFlow 原应用仍使用8082，两者不共用数据库。

首次启动会在private创建本地SQLite库。不能删除、覆盖或将运营库当作测试库。自动化测试创建单独临时目录，并只清理自己创建的测试目录。

Python商品生成依赖 Pillow、python-pptx，SVG渲染使用sharp/librsvg。当前机器已提供这些运行库；重建前检查运行环境并备份自己的作品。网站运行不需要这些制作工具。

## 目录职责

| 目录 | 用途 | 可否公开 |
|---|---|---|
| public | HTML/CSS/JS、公开商品数据和PNG预览 | 可在授权发布后公开 |
| server | 结算适配、会话、SQLite授权与受控下载 | 源码可审查，部署由服务端运行 |
| scripts | 商品生成、核验、打包工具 | 能重建收费图形的制作生成器属于私有资料，已从网站源码包和Git候选文件中排除；验证工具可审查 |
| private/products | 完整收费商品和ZIP | 私有，不应放进公开仓库或CDN |
| private/canva-designs.json | 经营者管理编辑链接和复制状态 | 私有管理资料 |
| private/store.sqlite* | 会话、订单与回调事件 | 私有，需要备份和访问控制 |
| .env | 本地或服务端安全配置 | 私有，不得提交 |
| docs/evidence | 脱敏验收记录 | 可按需审查 |

## 可部署环境

当前代码需要支持 Node 24 长驻进程、持久化磁盘与SQLite的运行环境。纯静态托管不能处理签名校验或私有下载；不能把public目录上传后宣称具备交易能力。

Sites 的托管服务运行于 Cloudflare Workers，不能直接运行本模块的 node:sqlite 与磁盘方案，因此本轮只采用本地开发流程，没有创建或发布 Sites 项目。若以后选择该托管环境，需要将数据库和私有文件改为受支持的D1/R2并重新验证，不能直接发布当前Node服务器。

在VPS等环境部署的最低步骤：准备受限系统用户与Node24；上传源码和私有商品到受限目录；通过安全渠道配置环境变量；绑定127.0.0.1，由HTTPS反向代理转发；设置准确的外部BASE_URL；配置进程守护、日志脱敏、数据备份与恢复；完成平台沙箱和全流程页面验收后再申请正式启用。不要让反向代理静态读取项目根目录或private。

## 数据维护和经营限制

测试回调重复事件由主键去重，订单下载关联已验证订单和会话，失败时不会自动交付。当前没有完整退款/争议吊销、邮件交付、账户找回、管理后台、自动收款核对或备份恢复验收。

Cookie会话默认30天，恢复凭据是持有人可恢复订单的能力凭据。页面只展示一次新建订单恢复凭据；如果结算首次响应丢失，同一会话仍能查询订单，但恢复凭据补发流程尚未实现。正式运营前需确定可靠的收据与恢复渠道。

默认没有发送邮件、购买域名、订阅或使用付费生成；公开发布、正式支付切换与经营政策需要经营者明确授权。
